# Physical implementation

LibreLane configuration for hardening `chip_top`. Run it with `make harden` from the
repository root; outputs land in `runs/` and `final/`, both gitignored.

## The files here

| File | Purpose |
| --- | --- |
| `config.yaml` | LibreLane flow configuration, `meta.version: 3` |
| `slot_1x1.yaml` | die and core geometry, pad ring order |
| `macros.yaml` | macro views and placement: LEF, LIB, GDS, netlist, coordinates |
| `chip_top.sdc` | timing constraints, used for both PnR and sign-off |
| `pdn/pdn_cfg.tcl` | power distribution network |
| `pdn/pdn_sram.tcl` | the grid over the sixteen SRAM macros |
| `gf180mcu_render.lyp` | KLayout layer properties for rendering |
| `build/sources.yaml` | the file list, generated by `synth/sources.sh`, not committed |

All of them are seeded from `librelane/` in the
[wafer.space project template](https://github.com/wafer-space/gf180mcu-project-template),
which is pre-tuned for `gf180mcuD` and the slot geometry, and each carries a header saying
what it changed and why. Start from it and diff, rather than writing configuration from
first principles.

`make harden` passes four of them, in order: `slot_1x1.yaml`, `macros.yaml`,
`build/sources.yaml`, `config.yaml`. Later files win on any key two of them set, and
LibreLane resolves `dir::` against the directory of the **last** file on the command line,
which is why they all live directly in this one.

There is no `macro_placement.cfg`, which an earlier version of this table asked for. The
template folds instance placement into the macro definition instead, and that is what
`Odb.ManualMacroPlacement` reads here; `macros.yaml` carries the sixteen coordinates.

## Settings that matter

The template's defaults encode hard-won knowledge. Change them deliberately, not casually.

- **Supply and corners.** Ticket 14 settled the core at 3.3 V, single supply, and the PDK's
  own `libs.tech/librelane/config.tcl` defaults to 5 V, so three settings have to be
  overridden after seeding from the template and nothing warns you if you miss one:
  `CELL_LIBS`, `STA_CORNERS` and `DEFAULT_CORNER`, rebuilt from `tt_025C_3v30`,
  `ff_n40C_3v60` and `ss_125C_3v00`. The library does not change:
  `gf180mcu_fd_sc_mcu7t5v0` carries all 229 cells at every one of its fifteen corners, and
  cell geometry is identical across them, so the supply choice costs no area. Three, not the
  four this section used to list: ticket 25 found that `VDD_PIN_VOLTAGE` is a **removed**
  variable in the LibreLane 3.1 in this container ("Information should be obtained from
  dotlib files", `config/removals.py`). Setting it is accepted in silence and never reaches
  `resolved.json`, so check that file rather than the config when a corner override looks
  like it did not take.
- **`SYNTH_LATCH_MAP` has to be set by hand.** `dfflibmap` maps flip-flops only, and
  upstream's `apb_soc_ctrl` infers two latches (`reset_reason[1:0]`; ticket 06's `bootsel`
  removal took the other two). The PDK ships the map and points `SYNTH_LATCH_MAP` at it, but
  LibreLane's gf180mcu compatibility shim **deletes that key** from the PDK configuration on
  the way in (`config/pdk_compat.py`), so it has to be set again in `config.yaml`. Without
  it the netlist carries unmapped `$_DLATCH_P_` cells and `Checker.YosysUnmappedCells` stops
  the flow.
- `CLOCK_PERIOD: 100` gives 10 MHz, ticket 05's settled target (ticket 24 moved the flow's own
  defaults there). Earlier in this map's history the setting was 50 ns / 20 MHz (revised from 40
  by ticket 14), and `make sta`'s headline against that target was bad news: Ticket 19 found
  that a plain `report_checks -group_path_count 1` reports the path with the worst raw arrival,
  which pre-layout is set by unbuffered fanout rather than by depth, so it moves identity under
  unrelated churn: the same netlist reported a 35-stage AXI crossbar path in one measurement and
  a 90-stage CV32E40P path in the next. Ticket 22 fixed this: `sta.sh` now asks OpenSTA for the
  300 worst-slack candidates in one query (`-group_path_count 300 -unique_paths_to_endpoint
  -format json`) and `path_summary.py` reports whichever of them has the most logic stages, with
  its rank among the 300 printed alongside so a candidate that only barely made the window is
  visible as such rather than silently trusted. Against the old 50 ns budget the design never
  closed 20 MHz at 3.3 V: 89 stages and a 62.3 ns floor at ticket 22 (125% of budget), 83 stages
  and 62.2 ns at ticket 23 (124%), essentially unchanged by the boot ROM's real RTL landing.
  **Ticket 24 re-measured against the real 100 ns budget for the first time** (`gf180_clk_gen.sv`
  and the reset synchroniser were the last RTL the clock decision was waiting on): 86 stages, a
  77.4 ns floor, **77% of the 100 ns budget at 3.3 V** — real margin, for the first time, because
  the budget caught up to what ticket 05 had already settled, not because the logic got faster.
  The 5.0 V logic-only arm is 85 stages, 51.0 ns, 51% of budget. The floor already assumes every
  stage gets its liberty-table delay with no wire RC, so real silicon will not do better than
  77.4 ns, only worse, until CTS and buffering exist to measure against; whether that margin
  survives a real clock tree is still open, and graduates only from a first full harden. The
  memory is not the limit either way: the OCD macro reports 13.46 to 15.87 ns at `ss_125C_3v00`,
  against a 100 ns budget.
- `PL_TARGET_DENSITY_PCT: 35`. Run 1 designs achieved 3k to 14k cells/mm², against a
  theoretical maximum several times higher. Plan against 8k to 12k. Ticket 25 measured what
  that target means here: global placement lands at **25.9%** standard-cell utilisation,
  comfortably under the target, and then `RepairDesignPostGPL` inserts about 61,000 buffers
  and takes it to **43.5%**. The target constrains the placement, not the netlist that comes
  out of repair.
- **`PL_MAX_DISPLACEMENT_X/Y: 1000`**, up from the template's 500 x 200. Those 61,000 buffers
  land on top of a placement that had already spread to the density target, and at the
  template's search distance `detailed_placement` could not find room for 425 of them and
  failed outright (`DPL-0036`). The core is only a quarter full at that point, so the space
  exists; it is further away than the default will look.
- **`OpenROAD.CTS` crashes on this design about twenty-four times in twenty-five, and has to
  be retried.** It is a null dereference in TritonCTS (`dbNet::get1stSignalInput` from
  `separateMacroRegSinks`), and it is intermittent rather than configuration-dependent:
  ticket 25 got one pass and then failed against the byte-identical resolved SDC that pass
  had emitted, from the same placement database. Retry the step until it succeeds, the way
  `make pdk` already retries magic:

  ```
  until make harden ARGS="--last-run --from OpenROAD.CTS --to OpenROAD.CTS"; do :; done
  ```

  Because of the crash rate, `chip_top.sdc` declares one clock rather than three: each extra
  clock is another tree to build and another chance to hit it. The TAP and the `/40` domain
  are still buffered by `repair_design` but get no balanced tree, so do not trust a
  gate-level JTAG timing result from this netlist. `chip_top.sdc`'s own header carries the
  stack trace, the exact constraints that would go back in, and the list of things that were
  tried and did not change the rate.
- Hold-slack margins are overfixed at 0.30 to 0.35 ns for a reason. Leave them alone.
- `PDN_CORE_RING_*WIDTH: 25`, because 30 µm is the maximum metal width before slotting rules
  apply.
- `MAGIC_GDS_FLATGLOB` carries a long list of cell patterns that must be flattened to avoid
  false DRC errors, most of them inside the foundry SRAM macros. Any new macro will need its
  own entries, discovered the hard way.
- `ERROR_ON_MAGIC_DRC: False`, because Magic DRC is not a submission gate. Review the
  violations anyway.

## SystemVerilog front end

**Settled: yosys-slang.** Yosys alone will not read upstream's RTL, which uses interfaces,
packages and packed structs across more than fifty files, but the `read_slang` plugin shipped
with Yosys 0.67 in the pinned container reads the whole SoC and elaborates `core_v_mcu` in
about three seconds. The PULP chain (Bender, Morty, SVase, sv2v) is not needed and Morty and
SVase are not in the container anyway. In LibreLane this is `USE_SLANG: True` with
`SLANG_ARGUMENTS: ['--keep-hierarchy']`.

Reproduce it with `make elaborate`, which runs `flow/synth/elaborate.sh`. That script asks
fusesoc to resolve upstream's unmodified `default` target from the submodule, filters the
eFPGA out of the resulting file list, adds `rtl/gf180mcu/` and `flow/synth/stubs.sv`, and runs
the front end. It ends by printing every module the design instantiates but does not define,
which is the work list for `rtl/gf180mcu/`.

**The liberty has to be read before the RTL.** As of ticket 16,
`rtl/gf180mcu/gf180_clk_gate.sv` instantiates three PDK cells by name, and yosys-slang will
import an instance as a black box only if some earlier yosys command already loaded that
module. `flow/synth/filelist.sh` resolves the standard-cell liberty and both `elaborate.sh`
and `area.sh` open with `read_liberty -lib` on it. LibreLane's own synthesis step already
does this, so no config setting follows from it, but a hand-written yosys script that reads
the RTL first will stop on an unknown module rather than degrade gracefully. Reading the
liberty is also what gives those cells real area in `stat -liberty` instead of zero.

Two settings the flow config has to match. `-D SYNTHESIS` is passed, which only disables
assertion blocks here; the `SCM_IMPLEMENTED` and `SCM_BASED_ICACHE` defines it switches on in
`pulp_soc_defines.svh` are referenced nowhere in the RTL. `PULP_FPGA_EMUL` is left undefined,
which is what selects the ASIC branches in `soc_domain.sv` and `safe_domain.sv`; fusesoc's
`default` target declares it as a parameter defaulting to true, so do not let a backend pass
it through.

## Synthesis must flatten

Not optional, and worth 1.30 mm² of cell area. The eFPGA slot is replaced by
`rtl/gf180mcu/gf180_efpga_stub.sv`, whose four TCDM master ports hold `req` low forever.
Flattened, constant propagation removes them completely: ticket 10 confirmed
`gen_l2_demux[5]` through `[8]` contain zero cells in the flat netlist while ports 0 to 4
survive. With module boundaries kept, nothing propagates across them, all nine master ports
are built in full, and the three crossbars arbitrate between nine masters instead of five.
Measured, that is 4.72 mm² hierarchical against 3.42 mm² flattened.

So do not set `SYNTH_HIERARCHY_MODE` to keep hierarchy, and if a future ticket wants
hierarchy preserved for some other reason, parameterise `N_EFPGA_TCDM_PORTS` down first.
`make area` runs both ways precisely so this stays visible.

Two other things synthesis needs, both discovered by ticket 10. `dfflibmap` maps flip-flops
only, and upstream's `apb_soc_ctrl` infers four latches (`r_bootsel[1:0]`,
`reset_reason[1:0]`), so the PDK's `libs.tech/librelane/$SCL/latch_map.v` has to be applied
or they survive as behavioural `always` blocks. And the design arrives at place and route
with no buffering at all on its highest-fanout nets: 10,122 loads on the SoC clock, 4,684 on
`apb_reset`, 4,290 on a debug-control net, twenty-three nets above 500. Clock tree synthesis
handles the first; the reset nets are `repair_design`'s problem and are worth checking
explicitly rather than assuming. These nets are also why a naive single-path `make sta` query
picks the wrong path, per the clock-period note above.

## Macro placement

Sixteen `gf180mcu_ocd_ip_sram__sram1024x8m8wm1`, fixed by ticket 11, instantiated by ticket
19, shaped by ticket 21 and placed by ticket 25. **Every signal pin on this macro is on
Metal2 in a 3 um band along one edge**, all 37 of them, so each macro presents its whole
interface on one side and orientation is not free. `macros.yaml` carries the coordinates:
two rows of eight along the south edge of the core, columns abutted at
`760.00 + n * 301.300`, rows at y 502.00 and y 1118.00.

Both rows are placed **FS**, not N. FS mirrors in y only, which turns the pin band upwards:
row 1's interface then faces the standard-cell region directly and needs no channel above the
array, and row 0's faces the 100.19 um channel between the rows. Placing them N would have
put row 0's whole interface against the core's south boundary with nowhere to escape but back
over the array.

`GRT_ALLOW_CONGESTION: true` is set in the template but is not a substitute for a floorplan.

## Sign-off

LibreLane finishing is not sign-off. Run `make precheck` and treat a clean precheck as the
definition of done. It checks top cell name and count, origin, database units, maximum metal
layer, slot dimensions, density, zero-area polygons, antenna rules, and DRC.
