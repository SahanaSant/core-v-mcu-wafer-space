# Flow configuration

The LibreLane setup that hardens `chip_top`. Run it with `make harden`; outputs land in
`flow/runs/` and `flow/final/`, both gitignored.

## Make targets

| Target | What it does |
| --- | --- |
| `make` | list the targets |
| `make shell` | open a shell in the toolchain container |
| `make pdk` | build the pinned GF180MCU PDK from source into `./pdk` |
| `make elaborate` | read the SoC RTL, list anything unresolved |
| `make area` | synthesise to standard cells, report logic area |
| `make sta` | report the deepest pre-layout path (needs `make area`) |
| `make bootrom` | build `sw/bootrom`, regenerate `gf180_bootrom.sv`, check it under Icarus |
| `make harden` | the RTL-to-GDS run. `ARGS=` passes flags to LibreLane |
| `make harden-cts` | retry clock tree synthesis until it survives |
| `make sync-final` | point `flow/final` at the newest completed run's views |
| `make sim` / `make sim-gl` | RTL and gate-level simulation |
| `make precheck-image` / `make precheck` | build and run the wafer.space submission checker |
| `make clean` | remove flow outputs, keep the PDK |

## The files

| File | Purpose |
| --- | --- |
| `flow/config.yaml` | LibreLane flow configuration, `meta.version: 3` |
| `flow/slot_1x1.yaml` | die and core geometry, pad ring order |
| `flow/macros.yaml` | macro views and placement: LEF, LIB, GDS, netlist, coordinates |
| `flow/chip_top.sdc` | timing constraints, used for both PnR and sign-off |
| `flow/pdn/pdn_cfg.tcl` | power distribution network |
| `flow/pdn/pdn_sram.tcl` | the grid over the sixteen SRAM macros |
| `flow/gf180mcu_render.lyp` | KLayout layer properties for rendering |
| `flow/build/sources.yaml` | the file list, generated by `flow/synth/sources.sh`, not committed |

All of them are seeded from `librelane/` in the
[wafer.space project template](https://github.com/wafer-space/gf180mcu-project-template),
which is pre-tuned for `gf180mcuD` and the slot geometry, and each carries a header saying
what it changed and why. Start from the template and diff, rather than writing configuration
from first principles.

`make harden` passes four of them, in order: `slot_1x1.yaml`, `macros.yaml`,
`build/sources.yaml`, `config.yaml`. Later files win on any key two of them set, and
LibreLane resolves `dir::` against the directory of the **last** file on the command line,
which is why they all live directly in `flow/`.

There is no `macro_placement.cfg`. The template folds instance placement into the macro
definition instead, and that is what `Odb.ManualMacroPlacement` reads here; `macros.yaml`
carries the sixteen coordinates.

## Scripts

`flow/synth/` holds the standalone measurement flow, which does not use LibreLane:

| Script | Role |
| --- | --- |
| `filelist.sh` | sourced; resolves the fusesoc file list and the Liberty files |
| `elaborate.sh` | `make elaborate` |
| `area.sh` + `area_report.py` | `make area` |
| `sta.sh` + `path_summary.py` + `strip_params.py` | `make sta` |
| `sources.sh` | writes `flow/build/sources.yaml` for LibreLane |
| `bootrom.sh` / `app.sh` | build the two software images |
| `buffer_report.py` | diagnostic: attribute inserted buffers back to the nets that caused them. No make target runs it. |

`flow/pdk/build.sh` builds the PDK; `flow/pdk/patch_ocd_sram.sh` corrects the OCD SRAM
Liberty as part of that build, so a rebuild reproduces the fix rather than losing it.

## Settings that matter

The template's defaults encode Run 1 and Run 2 shuttle experience. Change them deliberately.
Every one of these carries its full reasoning in `flow/config.yaml` next to the setting; this
is the index.

**Supply and corners.** The core runs at 3.3 V and the PDK's own
`libs.tech/librelane/config.tcl` defaults to 5 V, so three settings have to be overridden
together and nothing warns you if you miss one: `CELL_LIBS`, `STA_CORNERS` and
`DEFAULT_CORNER`. The library does not change — `gf180mcu_fd_sc_mcu7t5v0` carries all 229
cells at every one of its fifteen corners with identical geometry, so the supply choice costs
no area. `VDD_PIN_VOLTAGE` is a *removed* variable in LibreLane 3.1: setting it is accepted
in silence and never reaches `resolved.json`, so check that file rather than the config when
a corner override looks like it did not take.

**`SYNTH_LATCH_MAP` has to be set by hand.** `dfflibmap` maps flip-flops only, and upstream's
`apb_soc_ctrl` infers two latches. The PDK ships the map and points `SYNTH_LATCH_MAP` at it,
but LibreLane's gf180mcu compatibility shim deletes that key on the way in
(`config/pdk_compat.py`). Without it the netlist carries unmapped `$_DLATCH_P_` cells and
`Checker.YosysUnmappedCells` stops the flow.

**`CLOCK_PERIOD: 200`** is 5 MHz. See [explanation/timing.md](../explanation/timing.md) for
how that number was reached and the four software and testbench constants that track it.

**`PL_TARGET_DENSITY_PCT: 35`** is a ceiling the placer spreads under, not a target it has to
reach. Global placement lands at 25.9% standard-cell utilisation; `RepairDesignPostGPL` then
inserts about 61,000 buffers and takes it to 43.5%. The target constrains the placement, not
the netlist that comes out of repair.

**`PL_MAX_DISPLACEMENT_X/Y: 1000`**, up from the template's 500 × 200. Those 61,000 buffers
land on a placement that had already spread to the density target, and at the template's
search distance `detailed_placement` could not find room for 425 of them and failed outright
(`DPL-0036`). The core is only a quarter full at that point; the space exists, it is just
further away than the default will look.

**`EXTRA_EXCLUDED_CELLS`** keeps the delay-cell family away from the resizer. OpenROAD's
fanout repair takes the library's lowest-drive buffer, and this library puts all four delay
families at or above `buf_1` on drive resistance, so a fraction of a percent selects a cell
costing several times the intrinsic delay and area — and the result cascades, because each
slow weak stage re-violates slew at its own output.

**`MAX_FANOUT_CONSTRAINT: 40`**, up from the PDK default of 10, because that repair is
degenerate here. At 10 it builds 258 private chains of single-load buffers rather than a
tree, and the constraint does not survive the flow anyway. `MAX_TRANSITION` and
`MAX_CAPACITANCE` are the physically meaningful limits and their repair does build real
trees.

**`GRT_OVERFLOW_ITERS: 3`**, down from LibreLane's 50, because the loop restarts from
iteration 1 every time it disables a non-default routing rule on a congested net. The cap
does not change which nets end up NDR-disabled, only how long the router grinds before
conceding on each.

**Hold repair happens after global routing**, not at the post-CTS stage. This is the single
most counter-intuitive setting here and
[explanation/timing.md](../explanation/timing.md) covers it.

**`PDN_CORE_RING_*WIDTH: 25`**, because 30 µm is the maximum metal width before slotting
rules apply.

**`MAGIC_GDS_FLATGLOB`** carries a long list of cell patterns that must be flattened to avoid
false DRC errors, most of them inside the foundry SRAM macros. Any new macro will need its
own entries, discovered the hard way.

**`ERROR_ON_MAGIC_DRC: False`**, because Magic DRC is not a submission gate. Review the
violations anyway.

## SystemVerilog front end

**yosys-slang.** Yosys alone will not read upstream's RTL, which uses interfaces, packages
and packed structs across more than fifty files, but the `read_slang` plugin shipped with
Yosys 0.67 in the pinned container reads the whole SoC and elaborates `core_v_mcu` in about
three seconds. The PULP chain (Bender, Morty, SVase, sv2v) is not needed, and Morty and SVase
are not in the container anyway. In LibreLane this is `USE_SLANG: True` with
`SLANG_ARGUMENTS: ['--keep-hierarchy']`.

Reproduce it with `make elaborate`, which asks fusesoc to resolve upstream's unmodified
`default` target from the submodule, filters the eFPGA out of the file list, adds
`rtl/gf180mcu/` and `rtl/chip/`, and runs the front end.

**The Liberty has to be read before the RTL.** `rtl/gf180mcu/gf180_clk_gate.sv` instantiates
PDK cells by name, and yosys-slang imports an instance as a black box only if some earlier
yosys command already loaded that module. `flow/synth/filelist.sh` resolves the Liberty and
both `elaborate.sh` and `area.sh` open with `read_liberty -lib` on it. LibreLane's own
synthesis step already does this, so no config setting follows from it, but a hand-written
yosys script that reads the RTL first will stop on an unknown module rather than degrade
gracefully. Reading the Liberty is also what gives those cells real area in `stat -liberty`
instead of zero.

Two defines the flow config has to match. `-D SYNTHESIS` is passed, which only disables
assertion blocks here. `PULP_FPGA_EMUL` is left undefined, which is what selects the ASIC
branches in `soc_domain.sv` and `safe_domain.sv`; fusesoc's `default` target declares it as a
parameter defaulting to true, so do not let a backend pass it through.

## Synthesis must flatten

Not optional, and worth 1.30 mm² of cell area. The eFPGA slot is replaced by
`rtl/gf180mcu/gf180_efpga_stub.sv`, whose four TCDM master ports hold `req` low forever.
Flattened, constant propagation removes them completely: `gen_l2_demux[5]` through `[8]`
contain zero cells in the flat netlist while ports 0 to 4 survive. With module boundaries
kept, nothing propagates across them, all nine master ports are built in full, and the three
crossbars arbitrate between nine masters instead of five. Measured: 4.72 mm² hierarchical
against 3.42 mm² flattened.

So do not set `SYNTH_HIERARCHY_MODE` to keep hierarchy. If some future change wants hierarchy
preserved for another reason, parameterise `N_EFPGA_TCDM_PORTS` down first. `make area` runs
both ways precisely so this stays visible.

The design also arrives at place and route with no buffering at all on its highest-fanout
nets: 10,122 loads on the SoC clock, 4,684 on `apb_reset`, 4,290 on a debug-control net,
twenty-three nets above 500. Clock tree synthesis handles the first; the reset nets are
`repair_design`'s problem and are worth checking explicitly rather than assuming.

## Macro placement

Sixteen `gf180mcu_ocd_ip_sram__sram1024x8m8wm1`, two rows of eight along the south edge of
the core, columns at `760.00 + n × 302.300`, rows at y 502.00 and y 1118.00.

**Every signal pin on this macro is on Metal2 in a 3 µm band along one edge**, all 37 of
them, so each macro presents its whole interface on one side and orientation is not free.
Both rows are placed **FS**, which mirrors in y only and turns the pin band upwards: row 1's
interface then faces the standard-cell region directly and needs no channel above the array,
and row 0's faces the 100.19 µm channel between the rows. Placing them N would have put row
0's whole interface against the core's south boundary with nowhere to escape but back over
the array.

The columns do not abut. The 1 µm gap and the routing obstructions that go with it are
explained in `flow/macros.yaml` and
[explanation/known-issues.md](../explanation/known-issues.md).

`GRT_ALLOW_CONGESTION: true` is set in the template but is not a substitute for a floorplan.
